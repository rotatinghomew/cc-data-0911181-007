# 数据与业务契约

instance 缺失表示尚未明确归属，不能按 person 随意并入；day 精度保留整日而非零点事实。状态为台账快照，reopened 事件不会删除之前 completed 事实。dependencies 是已知必要先后，不表示其他事件全序。

## 数据集合

- `instances`：主键为 `instance`；必填字段 `instance, person, course, campus, opened, state`，当前 30 条。
- `events`：主键为 `event`；必填字段 `event, person, kind, time, precision`，当前 144 条。
- `pauses`：主键为 `pause`；必填字段 `pause, instance, start, reason`，当前 1 条。
- `dependencies`：主键为 `link`；必填字段 `link, before, after, meaning`，当前 2 条。
- `windows`：主键为 `campus`；必填字段 `campus, start, end`，当前 2 条。

集合中的主键不得重复；schema 的 foreign 引用须指向已存在的记录。可空字段保留 null 的业务含义，不自动补零。

## 查询与材料

GET 查询使用 UTF-8 JSON，错误参数返回 400，不存在的接口返回 404。重复的单值参数视为无效。summary 与 HTTP 调用同一组只读计算，材料包含数据内容指纹和生成时间，便于核对输入。当前输出描述已有数据，不承诺未实现的推断结论。

## 现有办理协作

人工以明确实例开协调单，assistance.allocate 分配校区协助名额，notices.send 在名额确认后发告知并保留当时原因。过程分析（见下节）为这些操作提供依据：findings 给出带证据的卡点，plan 给出名额内的优先顺序。

每个操作在本地业务日志的事务中更新；失败不提交半条办理记录。已有人工流程可以继续使用。接口传入业务标识，未知标识或不满足条件返回错误，不自动补建对象。

## 学习办理过程分析

只读接口：`/api/process/instances`（可选 `instance`、`person` 参数）、`/api/process/stages`、`/api/process/campuses`、`/api/process/findings`、`/api/process/plan`。summary 与 HTTP 使用同一组计算。

- 只按明确归属（含人工纠正后归属）的事件计算环节耗时；未归属事件仅按人员与时间窗列出候选实例（`candidates`），永不自动并入，同一人在同一天有两个合法报名也不会被串成一条路径。
- 任一端为 day 精度的环节只给出整天粒度（`granularity: day`，不出 `seconds`）；双端 second 精度才给秒级数值。
- 未结束流程按校区观察窗口右端计算删失等待（`wait_days`），单列分类，不计入已完成耗时，不视为失败，也不丢弃。
- 当前等待分类：`stuck`（超过同校区同环节已完成队列的最长用时，附 `reference` 参照）、`waiting`（未超参照）、`paused`（暂停记录覆盖窗口末端）、`indeterminate`（存在更晚的未归属事件，等待对象无法确定）、`repeated`（reopened 后的再办理）。参照队列排除暂停与再办理环节。
- 并行活动以 `parallel_instances` 标注（同学员其他在办实例时间窗重叠），作为上下文而非免责。
- `/api/process/campuses` 的 `overlap` 段只统计两校区窗口重叠期内完整观察到的实例，窗口外数据附左截断（`left_truncated`）说明，保证校区间可比较。
- `/api/process/plan` 按负责人名额输出 `covered`/`recommended`/`uncovered`；`uncovered` 一律标记 `status: unresolved`，名额不足时不把未覆盖实例说成已解决。

## 办理操作（分析接入后）

- `coordination.open_case`：可附 `evidence`（事件号列表）。证据事件须属于该学员；已归属其他实例的事件须先经 `events.reassign` 纠正。同一份材料（同一事件）已被其他在办协调单引用时，返回已有单并标记 `deduplicated`/`shared_material`，不新建互相冲突的第二张催办单。
- `events.reassign`：人工纠正误配事件（含确认未归属事件的归属），要求事件学员与目标实例一致。引用该事件的在办协调单改标 `evidence_moved` 并释放协助名额，原负责人不再背该项拖延；已发出的告知保持不变。
- `notices.send`：当前等待为 `paused` 或 `indeterminate` 的实例拒绝催促；发出的告知记录 `basis`（当时类别、等待天数、窗口末端、数据指纹），事后可解释当时依据。
- `assistance.allocate`：仅 `status=allocated` 占用名额；因 `evidence_moved` 释放的名额可再分配；非 open 状态的协调单不再分配。
